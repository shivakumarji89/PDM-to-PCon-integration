Creating new scene objects

There are two ways to create new scene element via create_oap. via a plain article number or via a metatype-object.

When creating a new scene object, OFML requires information about its position within the scene graph of the planning as well as the position and rotation of its geometry. The first is defined via the father object, the latter via an attach point(AP) provided by a reference object.

Creating a new object by an article number

The following example creates an interactor, that inserts an article, when clicking on it. The new object has to be placed as child of the selected object’s father. In other words: as sibling of the selected object.

11...
12
13# create interactor
14ia = Interactor("AddNeighborR", Symbol(SymbolType.Add, SymbolSize.large))
15
16# create an action, that creates a new object as sibling
17ac = oap.create_action_createobj("MyNewObject", oap.default_objects["parent"])
18
19# define package, article number and varcode for the new object
20ac.createobject.set_create_explicit("::man::series", "123456", "")
21
22# define reference object and AP of reference object to be used for
23# positioning the new object.
24ac.createobject.set_position_datadefined(oap.default_objects["self"], "ApSE_R")
25
26# add action to interactor
27ia.add_action(ac)

Creating a new object by a metatype

The next example shows the same as the example above, but using metatypes instead of plain articles.

10 ...
11
12 # use Metaytpe MT_SE_Table
13 mt_tables = data_man.get_package("man", "series").metatypes["MT_SE_Table"]
14
15 # create interactor
16 ia = Interactor("AddNeighborR", Symbol(SymbolType.Add, SymbolSize.large))
17
18 # get article objects for given list of article numbers
19 articles = mt_tables.get_articles_by_artno(["123456"])
20
21 # since we have only one article number, the list holds only one article
22 article = articles[0]
23
24 # create an action that creates a new object as sibling
25 ac = oap.create_action_createobj("MyNewObject", oap.default_objects["parent"])
26
27 # Use metatype's information for creation, such as article number,
28 # manufacturer, series.
29 # No "::man::series" or exact artno required.
30 ac.createobject.set_create_explicit_from_mt_article(article)
31
32 # define reference object and AP of reference object to be used for
33 # positioning the new object.
34 ac.createobject.set_position_datadefined(oap.default_objects["self"], "ApSE_R")
35
36 # add action to interactor
37 ia.add_action(ac)

Actually the metatype-solution looks more complicated. So, why bother? Because you can use metatype-infos for example for filtering or in conditions.

Use metatype info for filtering

If the oap-type is linked to a metatype, it can provide a lot of information about the article, such as properties and their values or values range. The order of values within a property, the article spec… These information could be used for filtering actions or creating conditions at the interactor.

The following example instead of adding a fix article number, creates a choicelist with an item for each article in MetaType MT_SE_Table. Additionally we want to see only articles with a fix height. And we want to see only options, with the same depth as the currently selected element.

 9 ...
10
11 # use Metaytpe MT_SE_Table
12 mt_tables = data_man.get_package("man", "series").metatypes["MT_SE_Table"]
13
14 # create interactor with an choicelist
15 ia = oap.create_interactor_choicelist("AddNeighborR")
16
17 # get the actionlist
18 ac_l = ia.get_actionlist("AddNeighborR")
19
20 # make for each article in this MT an action, that creates a corresponding article
21 for article in mt_tables.articles:
22
23     # filter variant 1: exclude articles entirely
24     # use only articles, that have value @SE_HA_Fix in property GSE_HeightAdjust
25     if article.poly_props["GSE_HeightAdjust"] != OfmlSymbol("SE_HA_Fix"):
26         continue
27
28     # Create an action that creates a new object as sibling.
29     # Use the article number as action-name.
30     ac = oap.create_action_createobj("Add_" + article.artno, oap.default_objects["parent"])
31
32     # Use metatype's information for creation, such as article number,
33     # manufacturer, series.
34     ac.createobject.set_create_explicit_from_mt_article(article)
35
36     # Define reference object and AP of reference object to be used for
37     # positioning the new object.
38     ac.createobject.set_position_datadefined(oap.default_objects["self"], "ApSE_R")
39
40     # filter variant 2: exclude article via a condition
41     # show only items, whose depth equals the depth of the currently
42     # selected table.
43     depth_of_new_article = article.poly_props["GSE_Depth"]
44     cond = f"GSE_Depth == {depth_of_new_article}"
45
46     # add action to actionlist, use article number for text and our condition
47     ac_l.add_item(ac, text = oap.get_or_create_text(article.artno), condition = cond)

As you can see the example uses two different ways of filtering. The first one excludes articles from being processed at all. These articles will never appear in the choicelist. The second way includes the article into the list, but shows it only if the condition applies.

The result in oap_actionlist will look like this:

...
ACL_AddNeighborR;1;GSE_Depth == 600;AC_CO_Add_123456;TXT_123456;
ACL_AddNeighborR;2;GSE_Depth == 600;AC_CO_Add_223456;TXT_223456;
...

Sorting the items in an actionlist

Since metatypes store articles in a dictionary the solution above might result in a differently ordered actionlist each time the script is run. To avoid this you should define an order. The easiest sortation would be an alphabetical one. The following example sorts articles by their line number in table go_articles.

21 # make for each article in this MT an action, that creates a corresponding article
22 # and sort them by their line number in go_articles
23 for article in sorted(mt_tables.articles, key = lambda art: art.line_no):
24
25     # use only articles, that have value @SE_HA_Fix in property GSE_HeightAdjust
26     if article.poly_props["GSE_HeightAdjust"].value != "SE_HA_Fix":
27         continue

Conclusion

The advantages of metatypes are obvious:

  1. save time when creating OAP

    • no need to type every single article number manually

  2. easy filtering

    • exclude items from this list by checking for properties, article numbers or even texts

    • create specific conditions

  3. easy maintenance

    Simply re-run the script if:

    • additional articles were added to the metatype

    • articles were removed from the metatypes

    • the article numbers have changed

    • articles were moved from one series to another, just ensure the new series is registered at the DataManager (q.v. add_meta_series)

    and all changes will apply automatically.
