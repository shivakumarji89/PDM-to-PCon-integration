MethodCalls

MethodCalls are a quite powerful tool. They are used to trigger OFML-functions via OAP, thus enabling you to add very specific behavior to your OAP, expanding the limits of standard OCD or even MetaType’s behavior.

A MethodCall needs to “know” the class (or interface) which provides the programmed function (directly or via inheritance) and which (oap)object is the target of the methodcall. The combination of target class (or interface) and target object is encapsulated in a MethodCallContext and allows convenient creation of MethodCalls for this particular class+object combination.

Defining a methodcall context

In order to use an OFML-method in oap-tables, the required class has to be known by the script. This has to be done exactly once for each class (and object). Just store the context to a variable and use this variable when calling your method.

It is recommended to store MethodCallContexts in global variables to allow script-wide access.

The 4 arguments are:

  1. The Oap instance (this should always be the oap instance provided by create_oap itself).

  2. fully qualified class name as string

  3. the object the method should be called upon (either a predefined or a custom object)

  4. basename is used for creating the methodcall-ID in our oap-tables and if not specified will use the classname. If there are multiple MethodCallContexts referencing the same class but with different objects, the basename is required to distinguish these methodcalls one from another.

Note

The script generates a new methodcall-id whenever the method is called with different arguments and reuses an existing id whenever the method is called with the same arguments multiple times. This methodcall-id is created with the basename. This means basenames have to be unique to ensure the created methodcall-ID is unique!

 1# MethodCallContext for a function of GoMetaType
 2GoMetaType = OapMethodCallContext(
 3    oap,
 4    "::ofml::go::GoMetaType",
 5    oap.default_objects["self"],
 6)
 7
 8# MethodCallContext for a function of MyPlanningGroup
 9# if the selected object is the planning group itself
10MyPlanningGroup = OapMethodCallContext(
11    oap,
12    "::man::series::MyPlanningGroup",
13    oap.default_objects["self"],
14    basename = "MyPlanningGroup", # basename optional
15)
16
17# MethodCallContext for a function of MyPlanningGroup
18# if the selected object is a direct child of the planning group
19# and therefore has to be called upon the father
20getPlanningGroup = OapMethodCallContext(
21    oap,
22    "::man::series::MyPlanningGroup",
23    oap.default_objects["father"],
24    basename = "getPlanningGroup", # basename NOT optional, since line
25                                   # is the 2nd time we reference
26                                   # MyPlanningGroup!
27)

Hint

Naming context variables similar to your class, results in methodcall looking very “familiar”.

Functions

MethodCalls can be used within oap expressions, for example to define a visibility rule for an interactor.

Simply append the method’s name to the classname with the . operator. Arguments can be given within the brackets. The optional argument type_ defines whether the function is of the class or the instance (default MethodCallType.Instance).

This returns a string suitable for an oap expression.

According to the MethodCallContexts defined above the following examples call getWidth upon different objects.

# getWidth called upon the selected object
ia.condition = MyPlanningGroup.getWidth() + " > 800"

# getWidth called upon the father of the selected object
ia.condition = getPlanningGroup.getWidth() + " > 800"

If the function requires arguments put them between the brackets:

# method with no arguments
GoMetaType.getWidth()

# method with a single argument (@Width)
GoMetaType.getPropValue(OfmlSymbol("Width"))

# static function with 2 arguments (@Arg1, int = 400)
GoMetaType.myStaticFunc(OfmlSymbol("Arg1"), 400, type_ = MethodCallType.Class)

Actions

If instead of a methodcall for use in an oap expression a real action is required, you may use the same syntax. Just attach .action to the end of your method’s name.

# action for a method with no arguments
ac = MyClass.doSomething.action()

# action for a method with 2 arguments (@MyProp, @MyValue)
ac = GoMetaType.setPropValue.action(OfmlSymbol("MyProp"), OfmlSymbol("MyValue"))

# action for a static function with 1 argument (@Arg1)
ac = MyClass.myStaticFunc.action(OfmlSymbol("Arg1"), type_ = MethodCallType.Class)

Note

Leading underscores are reserved for internal use, therefore method names must not start with “_”.
