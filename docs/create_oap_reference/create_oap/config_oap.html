Config_oap

Config_oap is the central file to describe the oap-data you want to create.

There you need to provide a few bits of information described below, afterwards you can proceed to describe the functionality you want to create using the objects in the following sections.

Attributes that can/must be set

oap_man

type: str (mandatory)

use this to specify the manufacturer you want to create oap-tables for (see DSR-key manufacturer)

oap_series

type: str (mandatory)

use this to specify the product line you want to create oap-tables for (see DSR-key program)

requires_create_oap

type: str (mandatory)

use this to specify the script version required for config_oap.py

It is recommended to specify the version you are currently using. (call create_oap.exe --version) Future releases of create_oap will be compatible as long as they have the same major number. If major version changes you may need to adapt your config_oap before you can use it with the new version. (see Version history for changes of a particular version.)

data_man

type: DataManager (provided)

This object is provided, but must be configured to work properly. (see Minimal config)

Availabale objects and types

oap

Instance of OAP. This is the central object you will interact with. It provides methods to conveniently create interactors, propedits etc.

Type

Central entry point for oap functionality (see: here for a detailed description).

OapMethodCallContext

Convenient helper class to work with methodcalls (see: here for a detailed description).

Interactor

Though oap provides convenience methods to create interactors, it can often be useful to manually create interactors in order to reuse existing actions etc. (see Interactors with different symbols for an example).

Symbol

Used in conjunction with manually created interactors (see Interactors for an example).

Object_MethodCall

Allows working with manually defined objects. (see Custom objects)
